1 · The game in one page

A Java command-line, turn-based restaurant game. The player is the manager: staff time is limited, so the manager decides which customers and orders come first. We build it in three runnable stages, each tagged in GitHub.

Base setting (must always be offered, so the TA can reproduce runs)

Turns18, always all of them (no early ending)
Tables2
StaffWaiter ×1 (one task per turn) · Chef ×1 (one prep unit per turn) · Cashier ×1 (one payment per turn, automatic)
ArrivalsOne customer at the start of turns 1, 4, 7, 10, 13, 16 (six in total)
VictoryAfter turn 18: ≥ 4 paid AND revenue ≥ $45 AND average satisfaction of paid customers ≥ 60. Otherwise Defeat.
Menu itemPricePrep units
Salad$9.001
Burger$15.001
Pasta$18.002

The three stages

StageAddsTag
1 · Basic operationRegular customers, menu, Waiter, Chef, Cashier, full turn sequence, victory and defeatstage-1
2 · Customer behaviourVIPCustomer, CriticCustomerstage-2
3 · New role and menu policyHost, ComboMeal, Happy Hourstage-3

General rules we must never break

  • Customers choose their own food, never the manager. Show the choice once the order is placed.
  • No game rules in the UI. The console only collects choices and displays state; rules live in domain and control classes.
  • Money in integer cents, shown as dollars with two decimals.
  • Works offline.
  • Invalid choice: explain why, ask again, and do not use up the staff task.
  • Different customer behaviour goes through the customer objects, never a chain of type checks (instanceof) in the controller.

6 · Rules cheat sheet

Every turn, in this order

StepWhat happens
StartShow: turn number, revenue, average satisfaction of paid customers, waiting queue, occupied tables, each customer's satisfaction, order status, staff tasks available.
1 ArrivalsScheduled customer joins the queue with satisfaction 100.
2 Manager choicesWaiter (at most one): seat a queued customer · take a seated customer's order · serve a READY order · Wait.
Chef (at most one): advance one order by one prep unit · Wait. May work on an order taken this turn.
3 Kitchen and servingWaiter acts before Chef. A dish can be served only if it was READY before the Waiter acts, so a dish finished this turn is served next turn at the earliest.
4 Eating and paymentServed on an earlier turn → READY_TO_PAY. Cashier pays at most one READY_TO_PAY customer, oldest first; one who became READY_TO_PAY this turn pays next turn at the earliest. Payment adds the bill, marks PAID, frees the table.
5 WaitingEvery waiting or seated-not-served customer loses satisfaction (min 0). At 0 they leave: order cancelled, table freed. Served / eating / ready-to-pay lose nothing.
6 ResultAfter turn 18: Victory if all three targets met, else Defeat.
EndShow served count, unhappy departures, revenue, average (N/A if nobody paid), turns used.

State machines

Customer
  WAITING ──seat──▶ SEATED ──take order──▶ ORDERED ──serve──▶ EATING
                                                                 │ next turn
                                                                 ▼
                                    PAID ◀──Cashier, later turn── READY_TO_PAY
  WAITING / SEATED / ORDERED ──satisfaction hits 0 at turn end──▶ LEFT
                                         (order cancelled, table freed)

Order
  PLACED ─▶ PREPARING ─▶ READY ─▶ SERVED ─▶ PAID
  (any state before SERVED) ──customer leaves──▶ CANCELLED

Stage 3 rules

  • Host: seats at most one queued customer per turn, in addition to the Waiter. The Waiter can still seat.
  • ComboMeal: two existing items; prep units = sum; price = 90% of the sum, rounded to the cent.
  • Happy Hour: once per game, switched on at turn start, lasts that turn and the next; show remaining duration. Orders taken while active get 20% off. Customers waiting for a table or food recover +15 at turn start (max 100). VIP discount first, then Happy Hour. Price locked at order time; old orders and departed customers unaffected.

7 · Git routine and tag steps

Daily routine

git switch main && git pull                 # start from the latest main
git switch -c a/customer-basics             # one branch per task: <letter>/<topic>
# ...work, build, test...
sh build.sh && sh test.sh                   # Windows: build.bat, test.bat
git add <files>
git commit -m "Add satisfaction floor at 0 so customers can't go negative (§3.2 step 5)"
git push -u origin a/customer-basics        # then open a PR and request a reviewer
git switch a/customer-basics && git merge main   # if main moved while you worked
Commit credit: run git config --global user.email and make sure it is an email on your GitHub account, or your commits won't count as yours.

Tagging a stage (all three present)

  • All PRs for this stage merged; main builds and tests pass
  • This stage's victory and defeat runs replay correctly
  • No future-stage code (Stage 1: no VIP, Critic, Host, Combo, HappyHour. Stage 2: no Host, Combo, HappyHour)
  • Snapshot docs/uml/stage-N.png committed
git switch main && git pull
git tag -a stage-1 -m "Stage 1: basic restaurant operation"
git push origin stage-1

# fresh-clone check

cd check-stage-1 && sh build.sh && sh test.sh && sh run.sh < runs/stage1-victory.txt
